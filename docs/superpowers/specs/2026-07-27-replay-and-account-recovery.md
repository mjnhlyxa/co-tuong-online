# Game Replay + Cross-Device Account Recovery

**Date:** 2026-07-27

## Goal

Two complementary features for commercial viability:
1. **Game replay** — view any finished game move-by-move with scrubber
2. **Cross-device account recovery** — user can keep their account when switching devices

---

## Feature 1: Game Replay

### Why
Players want to review finished games — learn from their mistakes, study opponents. Currently they can only see the final board state.

### Behavior
- Any finished game (status='finished') gets a "Xem lại" button
- Replay mode: scrubber to navigate through moves, auto-play button, position panel
- Shows board state at each move with notation
- Available to both players and spectators

### Data
- `Game.moves[]` already stores all moves with `boardSnapshot?` field (currently optional, but I need to ensure it's stored)
- Need to backfill snapshots for existing games OR reconstruct from initial board

### Approach
**Server-side: store boardSnapshot for every move**
- Modify `move/route.ts` to capture board snapshot when move is made
- Replay page: `?replay=1` query param OR `/game/[id]/replay` route
- New component: `<ReplayView gameId={id}>` with scrubber + auto-play

## Feature 2: Cross-Device Account Recovery

### Why
Currently `deviceId` is generated by `localStorage.deviceId` (UUID v4). Switch devices = new account, lose all stats. Major commercial problem.

### Approach: **Recovery Code (Recommended)**

Simple, frictionless, no email infrastructure needed.

**Flow:**
1. When player first registers, generate a recovery code:
   - Format: `ABCD-1234` (8 chars, group-friendly for manual entry)
   - Stored in `Player.recoveryCode` field
2. In settings page, show the code with copy button + warning: "Save this to recover your account"
2. On new device, on welcome modal, add "Khôi phục tài khoản" button
3. Recovery flow:
   - User clicks → modal with input field
   - Enters 8-char code
   - POST `/api/players/recover` with `code` and `deviceId`
   - Server finds player by code, sets their deviceId to the new one
   - Player is now logged in as the existing user

### Security Considerations
- Code is just `XXXX-NNNN` — 4 letters × 4 digits = 26^4 × 10^4 = 456M combinations
- For 8-char alphanumeric, we need more entropy
- Use `cryptographicallyStrong` random: 12-char alphanumeric (62^12 = 3.2 × 10^21) → effectively unguessable
- Rate limit: max 5 attempts per 10 min per deviceId
- Optional: log recovery events for audit

### Code Format
12-character base32: e.g., `K7H2-N8P3-9M4Q`
Or simple: 12 chars uppercase alphanumeric without dashes: `K7H2N8P39M4Q`
